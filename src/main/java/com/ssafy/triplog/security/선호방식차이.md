
# 🔐 JWT 기반 사용자 자원 보호 구현 방식 비교

## ✅ 전역 보안 필터 방식 (방법 2) - **선호되는 방식**

### 🌟 장점

#### 🔹 관심사 분리 (Separation of Concerns)
- 보안 로직이 비즈니스 로직과 분리되어 **코드가 깔끔**해집니다.
- 컨트롤러는 본연의 역할(데이터 처리 및 응답 반환)에만 집중할 수 있습니다.

#### 🔹 중복 코드 제거
- 여러 컨트롤러에 권한 검사 코드를 반복 작성할 필요가 없습니다.
- URL 패턴 기반으로 한 번만 정의하면 모든 관련 엔드포인트에 적용됩니다.

#### 🔹 일관성 유지
- 모든 보호된 리소스에 동일한 검증 로직 적용 → **보안 정책 일관성 유지**
- 새로운 엔드포인트 추가 시에도 URL 패턴만 등록하면 자동 적용

#### 🔹 유지보수성 향상
- 보안 정책 변경 시 한 곳만 수정하면 됨 → 유지보수 용이
- 전체 시스템의 보안 로직 파악이 쉬움

#### 🔹 실수 방지
- 권한 검사 누락 등의 실수 예방
- 보호 대상 URL을 명시적으로 관리하여 **보안 구멍 가능성 최소화**

---

## 🧩 컨트롤러 내부에서 직접 검사하는 방식

### 👍 장점

#### 🔸 세밀한 제어
- 각 엔드포인트마다 고유한 보안 로직 구현 가능
- 복잡한 권한 검사가 필요한 경우 유연하게 대응 가능

#### 🔸 디버깅 용이
- 관련 로직이 컨트롤러에 직접 위치 → 디버깅이 **직관적**

---

## 🛠️ 실무에서 많이 쓰는 방법: **메서드 수준 보안**

```java
@PreAuthorize("authentication.principal.userNo == #userNo or hasRole('ROLE_ADMIN')")
public List<MyDailyPlanDto> getMyPlanDetail(Long userNo) {
    // ...
}
```

### 💡 장점
- 전역 필터 방식의 장점 **(관심사 분리, 중복 제거)** 과
- 컨트롤러 방식의 장점 **(세밀한 제어)** 를 모두 제공

---

## 📌 종합 의견

| 상황 | 추천 방식 |
|------|------------|
| 대규모 시스템, 협업 환경 | **전역 필터 방식** 또는 **메서드 수준 보안** |
| 간단한 프로토타입 개발 | 컨트롤러 방식 (단기적) |
| 장기적으로 유지보수 고려 | 전역 필터 or 메서드 보안 방식으로 리팩토링 권장 |
