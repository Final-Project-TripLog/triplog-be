
# 🛡️ 게시글 권한 확인에 대한 보안 고려사항

## ⚠️ 프론트엔드 권한 제어의 한계

프론트에서 버튼을 숨기는 것만으로는 **보안에 충분하지 않습니다**. 다음과 같은 취약점이 존재합니다:

- **API 직접 호출 가능**  
  브라우저 개발자 도구, Postman 등을 이용하여 사용자가 직접 API 호출 가능

- **CSRF 공격 취약**  
  악의적인 사이트가 사용자의 인증 정보를 도용하여 요청 가능

- **프론트 코드 변조 가능**  
  클라이언트 코드는 신뢰할 수 없으며 쉽게 조작 가능

👉 따라서 **백엔드에서 반드시 권한 검증**이 필요합니다.

## ✅ 게시글 권한 확인 구현 방법

### 1. ❌ URL에 userNo 포함 방식 (비추천)
```
/api/planposts/user/{userNo}/post/{postNo}
```
- URL이 복잡해짐
- 게시글 소유자와 일치하는지 추가 조회 필요 → 비효율적

---

### 2. ✅ 컨트롤러 내부에서 권한 확인 (권장)

```java
@DeleteMapping("/{postNo}")
public ResponseEntity<String> deletePlanPost(@PathVariable Long postNo) {
    Long authenticatedUserNo = getCurrentAuthenticatedUserNo();

    if (!planPostService.isPostOwner(postNo, authenticatedUserNo)) {
        return ResponseEntity.status(HttpStatus.FORBIDDEN).body("권한이 없습니다.");
    }

    planPostService.deletePlanPost(postNo);
    return ResponseEntity.ok("여행 계획 게시글이 삭제되었습니다.");
}
```

---

### 3. ✅ AOP(Aspect-Oriented Programming) 방식

#### Aspect 클래스
```java
@Aspect
@Component
public class OwnershipChecker {
    @Before("@annotation(CheckOwnership) && args(postNo,..)")
    public void checkOwnership(JoinPoint jp, Long postNo) {
        // 인증된 사용자 ID와 게시글 작성자 비교
        // 불일치 시 예외 throw
    }
}
```

#### 컨트롤러 적용
```java
@CheckOwnership
@DeleteMapping("/{postNo}")
public ResponseEntity<String> deletePlanPost(@PathVariable Long postNo) {
    planPostService.deletePlanPost(postNo);
    return ResponseEntity.ok("여행 계획 게시글이 삭제되었습니다.");
}
```

## 🛠️ 권장 구현 방식 (방법 2 또는 3)

- URL 구조는 그대로 유지
- 인증 정보는 **JWT → SecurityContext → UserDetails**로부터 획득

#### 서비스 계층
```java
public boolean isPostOwner(Long postNo, Long userNo) {
    PlanPostDto post = planPostRepository.findById(postNo);
    return post != null && post.getUserNo().equals(userNo);
}
```

#### 컨트롤러 계층
```java
@DeleteMapping("/{postNo}")
public ResponseEntity<String> deletePlanPost(@PathVariable Long postNo) {
    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    CustomUserDetails userDetails = (CustomUserDetails) auth.getPrincipal();
    Long userNo = userDetails.getUserNo();

    if (!planPostService.isPostOwner(postNo, userNo)) {
        return ResponseEntity.status(HttpStatus.FORBIDDEN).body("권한이 없습니다.");
    }

    planPostService.deletePlanPost(postNo);
    return ResponseEntity.ok("여행 계획 게시글이 삭제되었습니다.");
}
```
